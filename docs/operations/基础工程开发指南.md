# 基础工程开发指南

日期：2026-10-30。用户明确要求进入开发并完成前后端基础工程。本轮以已确认的需求、原型和技术架构为依据，不新增业务模块。

## 1. 版本与工程结构

| 工具或依赖 | 本工程使用版本 |
|---|---|
| Java | 21；当前工作区便携版 Temurin 21.0.13+9 |
| Spring Boot / MyBatis Starter | 4.1.2 / 4.1.0 |
| Maven / Wrapper | 3.9.11 / 3.3.4 |
| MinIO Java SDK / OkHttp JVM | 8.6.0 / 5.1.0，与 SDK 依赖匹配 |
| Node.js / pnpm | 24 LTS / 10.30.3 |
| Vue / Vue Router / Pinia | 3.5.44 / 4.6.4 / 3.0.4 |
| TypeScript / Vite | 5.9.3 / 8.3.5 |
| Element Plus / ECharts | 2.14.7 / 6.1.0 |
| Vitest / Playwright | 5.0.5 / 1.64.1 |

精确前端依赖由 `frontend/pnpm-lock.yaml` 固定。后端由 Spring Boot BOM 与显式版本管理，不复制两套后端工程。MinIO SDK 的 OkHttp 5 是多平台制品，Maven 工程显式加入 `okhttp-jvm`，以提供实际 JVM 类。

后端基础包为 `com.yunshu.zhixue`：`bootstrap` 负责启动，`platform` 放置技术设施，`modules` 建立已设计的 14 个业务包边界。后续在模块内按实际需要添加 `contract/web/application/domain/infrastructure`，不提前填充空业务实现。

前端为 `frontend/apps/portal` 和 `frontend/apps/admin`，各自创建 Vue、Router、Pinia、请求客户端及会话状态。`packages/ui` 只共享视觉组件和主题，`shared` 共享 API 类型，`http` 共享请求工厂；公共包不导出跨端登录态单例。

## 2. 环境与启动

当前电脑的 `.tools` 包含本次下载并校验 SHA-256 的 Windows x64 JDK 21、固定 pnpm、Maven 缓存及 Playwright 浏览器；这些文件不提交版本控制。其他电脑安装 JDK 21 后设置 `JAVA_HOME` 即可，系统 Node 必须为 24 LTS。VS Code 可使用 Java Extension Pack、Vue Official、ESLint 和 Prettier 扩展，并将 Java 项目运行时指向 JDK 21。

保留根目录 `.env`，它含当前 Docker 账号的实际凭据。首次在其他环境准备时，参考 `.env.example` 和 [Docker 环境说明](开发环境-Docker-Compose.md)，先完成三个基础服务及 MinIO 桶初始化。

在项目根目录执行：

```powershell
node scripts/dev.mjs setup
```

脚本只在工作区准备 pnpm 并按锁文件安装前端依赖。Java 工具链由脚本优先选择 `.tools/jdk-21*`，其次使用 `JAVA_HOME`；Maven Wrapper 固定 3.9.11，编译目标强制为 Java 21。

分别在三个终端运行：

```powershell
node scripts/dev.mjs backend
node scripts/dev.mjs portal
node scripts/dev.mjs admin
```

以上为三个独立的长运行命令，不能在同一终端等待前一条结束后再顺序执行。默认地址为后端 `127.0.0.1:8080`、学员端 `127.0.0.1:5173`、管理端 `127.0.0.1:5174`。开发端口采用严格占用检查，冲突会报错，不自动换端口。

`scripts/dev.mjs` 使用 Node 原生 dotenv 解析根目录 `.env`，支持引号，将密钥仅传给后端子进程；前端子进程不接收该文件中的数据库、Redis 或 MinIO 密钥。没有把根目录设为 Vite 的 envDir，也没有以 `VITE_` 前缀暴露服务端配置。在 IDE 直接启动 Java 时，需要自行注入相同的环境变量，Java 应用本身不会把 dotenv 当 properties 解析。

## 3. 本轮已接入的基础能力

- 统一 API 信封、分页类型、服务端生成的请求 ID 与 `X-Request-ID`、参数和基础异常映射；错误不回显请求原文或凭据。
- JSON 使用 snake_case、拒绝未知字段；Instant 输出 UTC、固定三位毫秒，业务日通过 `Asia/Shanghai` 计算。
- Spring Security 默认保护业务入口，关闭默认表单、Basic 登录和默认退出接口，不生成可登录的默认账号。
- 两端分别提供已设计的 `/api/v1/portal/auth/csrf`、`/api/v1/admin/auth/csrf`。两个 Cookie 分别为 `PORTAL_SESSION`、`ADMIN_SESSION`，均 HttpOnly、SameSite=Lax、Host-only，并限制各自 API 路径。生产需设置 `SECURE_COOKIES=true` 并使用 HTTPS。
- Spring Session 使用同一 Redis 仓库内的独立会话记录，并在记录内绑定入口域；即使手动把学员 Cookie 值改名重放到后台，也会拒绝。默认匿名握手会话闲置超时 30 分钟，可用 `SESSION_TIMEOUT` 配置；记住登录寿命、身份类别、auth_version、角色与权限刷新将随真实账号模块实现。
- 写请求保持 CSRF 保护，前端按端获取令牌并发送 `X-CSRF-TOKEN`；失败写请求不会自动重放，登录/退出模块落地后需调用本端 `resetCsrf()` 并重新握手。
- MySQL/MyBatis、Redis、MinIO 应用账号连接配置；MinIO 调用有连接和总耗时上限；Actuator 就绪检查包含 db、redis、minio，健康详情不对外暴露。
- 两套可构建页面、懒加载路由、404 页面、独立 Pinia 状态；后台使用 Element Plus，图表依赖已声明，后续按需引入 ECharts。

CSRF 握手不代表已登录。账号密码登录、注册、角色权限、数据归属检查等业务流程尚未实现；受保护接口返回 401 属于当前预期行为。

## 4. 数据和配置边界

Flyway 已接入但默认 `FLYWAY_ENABLED=false`。本次没有导入 `scripts/sql/schema.sql`、创建业务表、写入默认管理员或样例数据，也不自动 baseline 现有数据库。业务模块开始实现时，将经审定的结构整理成版本化迁移并明确初始数据后再开启。

上传资源继续使用 MinIO 私有桶。当前已接入 SDK、配置及健康检查，实际上传/授权读取接口在文件用例实现时添加；不开放匿名桶，不将前端 HTML/JS/CSS 放入 MinIO。

AI、短信服务商尚未确定，本轮未添加假供应商、默认密钥或模拟成功的调用。Excel/Markdown 解析库按对应业务模块需要引入。

## 5. 验证命令

```powershell
node scripts/dev.mjs backend:check
node scripts/dev.mjs frontend typecheck
node scripts/dev.mjs frontend lint
node scripts/dev.mjs frontend format:check
node scripts/dev.mjs frontend test
node scripts/dev.mjs frontend build
```

`backend:check` 使用真实 Docker 依赖执行集成测试并打包；普通 `mvnw verify` 默认只运行不依赖外部服务的单元测试。两套前端产物分别位于各自 `dist`，后端产物位于 `backend/target`。

浏览器测试首次下载 Chromium，再执行：

```powershell
node scripts/dev.mjs frontend exec playwright install chromium
node scripts/dev.mjs frontend test:e2e
```

E2E 会启动临时后端与两个前端，测试结束后关闭它们，保留 Docker 服务。测试前应停止占用 8080、5173、5174 的开发进程，避免误用其他实例。浏览器放在 `.tools/browsers`，失败痕迹在 `frontend/test-results`。
